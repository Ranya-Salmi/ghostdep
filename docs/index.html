How it works

Five checks, one verdict

GhostDep runs five deterministic checks. The most severe result becomes the verdict; a BLOCKED package is never installed.

Step 1
Agent requests a package
An AI agent generates a pip install command — could be a hallucinated name, a typo, or a real package.
→
Step 2
GhostDep runs 5 checks
Existence · Age · Popularity · Typosquatting (OSA distance vs top-5,000) · Vulnerabilities (OSV). Each check returns SAFE, SUSPICIOUS, or BLOCKED.
→
Step 3
Bob installs only what's safe
SAFE → install proceeds. SUSPICIOUS → flagged for review. BLOCKED → install refused; agent picks a real alternative.

Works everywhere

One tool, three surfaces

GhostDep plugs in at the exact moment a package name is chosen — whether that's inside an AI agent, a CI pipeline, or the command line.

IBM Bob (MCP server + skill + custom mode) AI agent
Register as an MCP server via Bob Settings → MCP → + (project scope), then activate the Dependency Guardian mode or the ghostdep-guard skill. While active, Bob checks every new package with check_package() before installing it. 
// Bob MCP config (project scope)
{
  "mcpServers": {
    "ghostdep": {
      "command": "path/to/.venv/Scripts/python.exe",
      "args": ["-m", "ghostdep.server"],
      "cwd": "path/to/ghostdep"
    }
  }
}
CLI — check a single package or scan a whole file Command line 
# Check, then install only if safe (drop-in for pip install)
ghostdep install requests python-dateutil

# Check one package
ghostdep check reqeusts

# Scan requirements.txt — exits 2 if any BLOCKED
ghostdep scan requirements.txt

# Generate a self-contained HTML report
ghostdep report requirements.txt --output report.html

# Watch the live PyPI feed for new lookalikes
ghostdep scan-new

# Allow internal packages, deny risky ones: .ghostdep.toml
[policy]
allow = ["acme-internal-auth"]
deny  = ["pycrypto"]
GitHub Actions CI gate CI/CD
Scans every PR that touches requirements.txt or pyproject.toml, uploads SARIF to the GitHub Security tab, and fails the job on BLOCKED packages. 
# abridged
# .github/workflows/ghostdep.yml
on:
  pull_request:
    paths: ["requirements.txt", "pyproject.toml"]

jobs:
  ghostdep-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: ghostdep scan requirements.txt --format sarif > ghostdep.sarif
      - uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: ghostdep.sarif
